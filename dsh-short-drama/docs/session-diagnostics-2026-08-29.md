## 已确认问题

### 1. 全剧大纲标题 Interface 与实现不一致

`screenplay_create_outline` 只提示“大纲标题使用项目文件夹名”，但校验实现只接受：

```text
# 《项目文件夹名》全剧大纲
```

错误结果没有把内部已有的 `expected`、`actual` 和具体修复方式暴露给 Agent。Agent 因而连续尝试 19 种标题写法，全部返回同一条笼统错误。

验收要求：

- 删除不必要的固定措辞校验，只保留 H1 和项目名等真正的格式事实；或明确把唯一合法格式发布在工具 Interface 中。
- 所有 A 信道失败都返回结构化 `artifact`、`location`、`expected`、`actual` 和 `repairHint`。
- 用真实工具调用测试覆盖“错误可直接修复”，不能只测试 Store 内部知道正确 fixture 的成功路径。

### 2. Agent 缺少相同错误熔断

同一工具、同一错误码、同一 Artifact/字段连续失败后，Agent 仍继续猜测并调用，且尝试读取项目外源码定位实现。

验收要求：

- 相同结构化错误连续出现 2 次后，不再无信息增量地重试。
- 有明确 `repairHint` 时按提示修一次；仍失败则停止并报告实际阻塞。
- 路径权限错误不能触发继续搜索项目外实现。

### 3. 初始化工具 Interface 过重且不自描述

`screenplay_create_contract` 一次要求合同、核心设定、全部主要人物和其他人物。首次调用缺少三个必填字段，第二次把完整参数错误编码成字符串，第三次才成功。大量正文因此被重复生成和重新传输。

验收要求：

- 工具 Interface 必须让模型在调用前获得完整必填结构和当前 Artifact 格式要求。
- 评估把“讨论中的内容组装”与“正式原子提交”分开，正式写入仍保持单次原子性。
- 增加真实模型形状的工具参数集成测试，覆盖嵌套长文本对象。

### 4. 模型重试显著放大等待时间

- 第 10 步出现 5 次 `TRANSPORT` 重试，耗时约 72 秒。
- 第 44 步出现 2 次 300 秒流空闲超时和 2 次流传输失败，单步耗时约 25 分 16 秒。
- 会话使用 `reasoningEffort: high`；错误循环期间产生大量重复推理。

验收要求：

- UI 明确区分“模型正在推理”“供应商重试”“工具执行”和“等待用户”。
- 对 300 秒流空闲超时提供可见状态和可取消入口。
- 常规格式修复不使用高强度开放式推理；先通过结构化校验反馈完成确定性修复。

### 5. 上下文目录仍偏宽

首轮包含 29 个工具的 schema 和多项与短剧无关的用户 Skill 摘要。它不是本次 25 分钟停顿的直接原因，但会增加首轮输入、路由噪声和错误恢复成本。

验收要求：

- 保持 Skill 正文按需加载。
- 评估 Skill 目录摘要的相关性裁剪，不影响用户显式 `/skill-name` 调用。
- 清理短剧 Agent 不再使用的旧领域工具，避免新旧工作流同时进入工具目录。
