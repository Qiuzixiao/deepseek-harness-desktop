# Zenwit — 短剧创作工作台产品构思与设计（历史 v0.2）

> 状态：历史构思，仅用于追溯，不是当前产品或内核运行契约。本文中的 `.screenplay`、固定目录、短剧状态、专用工具、A/B 信道、草稿、版本和交付流程均未加载。当前实现以 `dsh-short-drama/README.md` 和桌面通用工作区代码为准。

## 1. 产品概述

- **产品名**：Zenwit（代码名 dsh-short-drama）。
- **一句话**：以短剧项目为中心的 AI 创作工作台——项目库管理 + 结构化写作 + AI 对话协作，把"聊天写短剧"升级为"管项目、写结构、AI 协作"的一体化产品。
- **定位**：面向短剧编剧/工作室的桌面创作工具，跑在 DeepSeek Harness（DSH）之上，深度定制外壳（B 路线：替换 AppFrame）。
- **价值主张**：
  1. **项目化**：一个剧一个项目，大纲/集纲/角色/正文/参考/交付全在一个工作台里，不用在聊天记录里翻找。
  2. **结构化**：短剧基础格式（正文场次/动作/台词、第三人称集纲、合同/设定/角色事实结构）由系统约束与校验；具体题材、节奏和写法由用户与可选 Skill 决定。
  3. **AI 协作**：对话、写作、诊断、修改在同一界面完成，AI 是编剧的协作者而非替身。
- **核心用户场景**：
  - 灵感来了 → 新建项目 → 对话梳理创意 → 用户确认方向 → 写大纲 → 排分集 → 按场写正文 → 诊断 → 用户决定后交付。
  - 已有大纲/剧本 → 导入项目 → 结构化重构 / 按 DLKJB 重写。
  - 团队协作（远期）：项目文件即团队共享资产。

## 2. 信息架构

```
Zenwit
├── 首页（项目库）
│   ├── 项目列表/卡片（筛选、排序、搜索）
│   ├── 新建项目（仅命名 → 建目录 + 标记 → 进入工作台，规格交给对话）
│   ├── 导入项目（选择已有 .screenplay 目录）
│   └── 设置（项目库根目录、模型、默认规格）
└── 工作台（单项目，三栏）
    ├── 左栏：项目结构树 + 项目状态
    ├── 中栏：通用文档编辑器（未保存编辑 + 可选校验）
    └── 右栏：AI 对话（内嵌 DSH 会话）
```

## 3. 页面设计

### 3.1 首页（项目库）

| 元素 | 内容 | 数据来源 |
|---|---|---|
| 项目卡片 | 项目名（= 文件夹名）、一句话卖点、题材、状态徽标、集数进度（已完成/总集数）、最近修改时间 | 扫描项目库根目录下 `.screenplay` 标记目录 + 读各项目 `state.json` |
| 状态徽标 | 构思中(Intake) / 创作中(Ready) / 有未决修改(ChangePending) / 已完成(DeliveryReady) | 内核 phase + writingProgress |
| 新建项目 | 仅命名（必填）→ 创建目录 + `.screenplay/launcher` + layout.json → 进入工作台；平台/总集数/时长档等规格全部在 Intake 对话阶段由 AI 提问确认后写入 requirements | 内核 prepareProject / launcher 流程 + 对话确认 |
| 导入项目 | 目录选择器选已有 `.screenplay` 目录 → 校验 → 加入项目库 | 内核 detectScreenplayLayout |
| 项目库设置 | 根目录路径（默认 `~/ShortDrama`）、模型偏好、默认规格 | 设置服务 |

首页行为：无会话态即首页；点项目卡片 → 打开该项目的会话（工作台）；返回首页 → 会话保留可恢复。

### 3.2 工作台三栏

**左栏：项目结构树**
- 顶部：项目名 + 状态徽标（phase/revision）。
- 树节点（= 内核 artifacts 的逻辑路径）：
  - 创作合同（创作合同.md）
  - 设定（核心设定.md）
  - 人物：主要人物/<角色名>.md、其他人物/其他人物.md
  - 大纲：总纲.md
  - 分集大纲：分集大纲.md
  - 正文：第001集.md … 第NNN集.md（只列出已生成集数 + 下一集占位）
  - 参考文件（参考文件/）
  - 交付（交付/<项目名>.md，仅存在时显示）
- 节点状态提示：待确认字段数（角色）、字数/集数进度和校验结果。
- 底部操作：诊断当前集或项目（`diagnose_episode`）、版本历史、新建/导入参考文件。
- 新建节点：正文下一集（触发对话创作）、参考文件上传。

**中栏：文档编辑器**
- 顶部工具栏：文档名、保存状态（已保存/未保存）、校验状态（绿/黄/红）、操作（保存、诊断本文档、预览切换）。
- 编辑区（CodeMirror 6 定制）：
  - 大纲/集纲/合同/设定/角色：Markdown 编辑 + 预览（合同/设定/角色为模板字段视图；集纲/大纲为叙事文档视图）。
  - 正文（第 N 集）：DLKJB 结构化编辑——场次头/人物行/动作行/台词/OS/VO/闪回/卡点特写语法高亮；即时结构校验（标题、场次、人物、动作、台词、集尾、字数档）；底部有效字符数 vs 目标范围。
- 底层编辑：当前文档工作文件；未保存内容只属于编辑器本地状态，保存后即更新正式文件。
- 正文特殊处理：新建/续写正文走右栏对话，生成完整正文后调用 `write_episode` 直接写入正式剧本；`validate_episode` / `diagnose_episode` 仅在用户需要时调用。

**右栏：AI 对话（内嵌 DSH 会话）**
- 复用 ui-conversation 能力：消息流、输入、模型选择、工具卡片、历史、暂停/继续。
- 会话与项目绑定：打开项目即创建/恢复绑定会话（会话 cwd = 项目目录，内核 recoverBindingForSession 恢复）。
- 每轮对话自动注入项目状态摘要（内核 contextSummary 已有）。
- 对话快捷键：/diagnose（诊断项目）、/deliver（合并交付）、/outline、/next（写下一集）等（或纯对话触发）。
- 会话管理：重命名/清除/多会话（远期）。

## 4. 数据模型

```
ProjectLibrary（项目库）
└── <root>/                        # 可配置，默认 ~/ShortDrama
    └── <项目名>/                  # 项目 = 目录
        ├── 参考文件/
        ├── 创作合同/创作合同.md      ← 内核 artifact
        ├── 设定/核心设定.md
        ├── 人物/主要人物/<角色名>.md
        ├── 人物/其他人物/其他人物.md
        ├── 大纲/总纲.md
        ├── 分集大纲/分集大纲.md
        ├── 剧本/第NNN集.md
        ├── 交付/<项目名>.md
        └── .screenplay/
            ├── launcher/          # 桌面端创建标记
            ├── layout.json        # 布局标识（zh-CN-v1）
            ├── state.json         # 持久化权威源（内核）
            ├── events.jsonl       # 事件日志
            ├── versions/          # 版本化 artifact 副本
            └── references/        # 参考文件解析缓存
```

- **Project**：目录 + .screenplay 状态；projectName = 目录名 = 全项目唯一正式标题。
- **Document（artifact）**：合同/设定/人物/大纲/集纲/正文/交付，由内核按 kind 管理。
- **Formal file**：正文写入即成为项目正式文件，并由内核版本流记录；编辑器未保存内容不进入项目状态。
- **Session**：与项目绑定（会话 cwd = 项目目录）；项目 ↔ 主会话 1:1，对话中可派生子会话做专项任务。

## 5. 产品状态机（映射内核 phase）

| 阶段 | 内核 phase | 首页徽标 | 工作台引导 |
|---|---|---|---|
| 构思中 | Intake（有 launcher 无合同） | 构思中 | 右栏对话引导梳理创意 → 确认方向 → 创建合同 |
| 创作中 | Ready（有正式文件） | 创作中 | 大纲→集纲→正文逐阶段推进 |
| 有未决修改 | ChangePending | 待保存 | 弹「保存修改/不保存」 |
| 已完成 | Ready + DeliveryReady | 已完成 | 交付文件可导出 |

## 6. 双层写入语义

- **正文写入**：`write_episode` 接收完整正文，直接原子写入正式剧本并生成新 revision；默认不自动校验、不等待确认。
- **主动校验**：用户需要时调用 `validate_episode` 或 `diagnose_episode`，结果用于修正和决策，不阻塞已写入的正式文件。
- **已有正文修改**：使用 `screenplay_edit_file` 直接保存；系统自动保留旧版本，用户不需要处理中间状态。
- **诊断**：`diagnose_episode` 返回信道 A 校验和可选的信道 B 观察问题；创作建议不阻止用户提交。

## 7. 会话生命周期

- **1:1 主会话**：打开项目 → 查找/创建绑定主会话（会话 cwd = 项目目录）→ 右栏展示；返回首页 → 主会话保留可恢复；再次打开项目 → 恢复主会话（保留上下文）。
- **可开子会话**：对话中可派生子会话做专项任务（如「大纲讨论」「某一集重写」），完成后结果回到主会话；子会话不改变项目绑定。
- 会话内状态：每轮自动注入 contextSummary；工具调用卡片在消息流中展示。

## 8. 与内核的映射（UI ↔ 服务/工具）

| UI 行为 | 内核能力 |
|---|---|
| 首页项目列表 | 新能力：项目库索引（扫 root + 读各项目 state.json）；当前内核为 per-session cwd 绑定，需新增 list-projects 服务 |
| 打开项目 | 会话创建/恢复 + 绑定（cwd=项目目录，recoverBindingForSession） |
| 结构树 | snapshot('artifacts') 的 logicalPath 列表 + 各文件状态 |
| 编辑器 | 未保存内容留在编辑器本地；保存后写入正式文件 |
| 正式提交 | prepareChange + saveChange / discardChange |
| 诊断 | diagnose_episode + optional review lenses |
| 新建正文 | read_project_context + read_artifact + write_episode（按需 validate_episode / diagnose_episode） |
| 参考文件 | 参考文件/ 目录 + 上传/选区读取（references 服务） |
| 交付 | screenplay_merge_delivery |
| 版本历史/恢复 | versions + restoreVersion |
| 右栏对话 | 内嵌 ui-conversation（复用会话全能力） |

## 9. 非功能需求

- 性能：千字文档编辑不卡顿（CodeMirror 6 虚拟化）；项目库扫描 < 1s（延迟加载各项目状态）。
- 数据安全：项目文件即普通文件，不加密；.screenplay 私有状态目录权限 0700。
- 多平台：Electron 桌面（macOS/Windows/Linux），同一内核与 Web UI。
- 可扩展：新建文档类型/自定义模板（远期）。

## 12. 附录：DSH 客户端扩展机制（已查证）

- AppFrame 注册进 runtime 的 root 槽，声明 4 子槽：sidebar（左列）/ conversation（中列，session-maybe 双态）/ details（右列）/ frame（悬浮层）；**注册即替换**。
- client 模块声明：package.json `"dsh": { "client": { "inject": [...], "platform": "web" } }` + exports `./client`；由 client runtime 扫描加载。
- 会话 UI 可内嵌：ui-conversation 为独立 client 包，导出 ConversationController / IConversation 等服务。
- 内核持久化：.screenplay/state.json 为权威源（rc.2 不持久化自定义 session 事件，已适配）。
