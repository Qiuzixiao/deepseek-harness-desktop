# PRD-02：用户 Skill 安装与复用

状态：提案

## Problem Statement

用户可能已经有自己的写法、工作流、题材资料或审查清单，但当前不能通过自然语言把这些资料安装为可复用 Skill。用户也无法清楚知道某个 Skill 来自哪里、适用于哪些项目、是否会影响当前 Agent。

如果安装过程直接把资料当成系统提示词，可能导致 Skill 伪装成硬规则、覆盖用户选择，甚至误以为 Skill 可以授予文件权限。

## Solution

用户可以通过自然语言安装本地 Skill：

> 把我选中的这个 Skill 安装到我的用户空间，短剧项目可以使用，小说项目不要自动使用。

系统先检查 Skill 的名称、说明、资源引用和作用域，展示来源、内容摘要、适用范围和安全提示。用户确认后，Skill 原子安装到指定作用域。

安装后，Skill 可以被自然语言自动匹配，也可以显式调用。用户可以查看、启用、停用、更新和卸载 Skill。所有 Skill 都只是参考知识，不能扩大文件权限，也不能直接修改项目正式文件。

## 真实使用场景

用户：

> 我有一套自己的短剧写法资料，帮我安装。只在短剧 Agent 里使用。

Agent：

> 我识别到这是一个名为“克制对白”的 Skill，包含写法说明和 4 个参考文件。它会影响台词建议，但不会改变文件权限。安装范围是用户空间，是否安装？

用户确认后，Skill 可在短剧项目中使用。

用户之后说：

> 这次先不用“克制对白”，但不要卸载。

Agent 临时停用它，当前项目仍然可以继续创作。

## User Stories

1. 作为编导，我希望通过自然语言安装自己的 Skill，以便不用学习后台配置。
2. 作为编导，我希望安装前看到 Skill 名称、来源、资源和适用范围，以便确认它是什么。
3. 作为编导，我希望选择 Skill 安装到用户空间或项目空间，以便控制影响范围。
4. 作为编导，我希望指定 Skill 默认适用于短剧、小说或其他领域，以便避免误匹配。
5. 作为编导，我希望安装前知道 Skill 是否包含无法读取或不支持的资源，以便处理失败。
6. 作为编导，我希望安装失败时不会留下半套文件，以便保持 Skill 目录干净。
7. 作为编导，我希望查看已安装 Skill 的版本和来源，以便判断当前使用的是哪一版。
8. 作为编导，我希望临时停用 Skill，而不是必须卸载，以便进行对照创作。
9. 作为编导，我希望更新 Skill 时保留旧版本，以便在新版本不合适时恢复。
10. 作为编导，我希望卸载 Skill 不影响已经完成的项目和正式剧本，以便安全清理。
11. 作为编导，我希望 Skill 只能提供建议，不能擅自修改文件或改变系统权限。
12. 作为编导，我希望在冲突的 Skill 同时匹配时看到来源和差异，以便自己选择。

## Implementation Decisions

- 支持的安装来源包括用户明确选择的本地目录或压缩包；网络来源和市场目录另行设计。
- 第一版只安装声明式 Skill 资源，例如 `SKILL.md`、Markdown 参考资料和模板；不执行 Skill 内脚本或程序。
- Skill 必须通过名称、描述、调用方式、资源引用和资源大小检查。
- 安装目标明确区分用户作用域和项目作用域；默认不把项目 Skill 自动暴露给其他项目。
- 安装采用临时目录校验后原子替换；更新和删除也必须可恢复或有明确失败结果。
- 同名 Skill 不静默覆盖。系统展示已有版本，由用户选择更新、另存为新名称或取消。
- Skill 的匹配依据包括用户任务、领域范围和用户启用状态；未启用的 Skill 不自动注入上下文。
- Skill 内容不能声明新的工具、文件根目录、网络权限或提交权限；这些由 Harness 和领域 Agent 决定。
- Agent 回复中应说明当前使用了哪些 Skill，以及建议来自 Skill 还是模型推断。
- 后续的 `skill_inspect`、`skill_create`、`skill_install`、`skill_update`、`skill_remove` 作为受控生命周期能力，但用户主入口仍是自然对话。

## Testing Decisions

- 测试用户从本地目录和压缩包安装、取消、更新、卸载的外部结果。
- 验证缺少 `SKILL.md`、名称非法、资源路径越界、符号链接逃逸和过大资源会被拒绝。
- 验证安装失败不会留下残缺 Skill，也不会修改原来源目录。
- 验证用户作用域和项目作用域隔离，Skill 只在授权范围内可见。
- 验证停用 Skill 后任务仍能运行，启用后才能被自动匹配。
- 验证同名更新不覆盖旧版本，且可以恢复。
- 验证 Skill 不能调用项目外读取、通用写入、Shell 或正式提交能力。
- 验证两个 Skill 给出不同建议时，Agent 展示差异而不是静默覆盖。

## Out of Scope

- Skill 市场、评分、付费和第三方网络安装。
- 执行 Skill 内的任意代码或把 Skill 变成插件。
- 自动把所有已安装 Skill 同时加载到每次对话。
- 自动判断用户 Skill 的创作价值或正确性。
- 独立 Skill 后台作为唯一管理入口。

## Further Notes

安装 Skill 的本质是“给 Agent 增加一份可选参考”，不是“给 Agent 安装一个拥有新权限的程序”。这个区别必须在产品文案、运行时和安全测试中保持一致。
