# PRD-03：首页灵感库

状态：提案

## Problem Statement

创作者在对话中会不断产生人物、冲突、场景、台词和故事 premise，但这些内容通常散落在聊天记录、笔记和外部文件里。用户需要一个地方暂存它们，又不希望这些内容未经选择就污染当前项目或变成 Agent 的永久规则。

灵感库如果只是内容瀑布流，无法解决“这条灵感接下来怎么用”的问题；如果自动把内容加入项目，又会混淆灵感、项目事实和 Skill。

## Solution

首页提供一个轻量的灵感库。用户可以从当前对话、项目或外部资料中保存灵感，并为它添加标题、类型、标签、来源和备注。

灵感默认处于“未进入项目”的状态。用户可以在自然语言中搜索、组合和调用灵感：

> 找出灵感库里三个适合当前短剧的冲突点，先给我比较，不要写进剧本。

用户选择后，可以把灵感作为当前任务参考、加入项目草稿、登记为项目事实，或作为 Skill 提炼案例。每一步都需要清楚区分其状态。

## 真实使用场景

用户在创作中说：

> “她明明拿到了证据，却不敢马上公开”这句先存起来。

灵感库保存内容并记录来源为当前会话。

几天后用户说：

> 从我的灵感库里找几个适合这部剧第二集的冲突点。

Agent 返回候选项，并说明哪些来自灵感库、哪些是它的组合推断。用户说：

> 用第二个，但先放在第二集草稿里，不要提交。

系统只把它送入当前草稿，不修改正式剧本。

## User Stories

1. 作为编导，我希望从对话中一键保存灵感，以便不打断创作。
2. 作为编导，我希望保存人物、冲突、场景、台词和 premise 等不同类型的灵感，以便后续整理。
3. 作为编导，我希望记录灵感来源和时间，以便回忆它从何而来。
4. 作为编导，我希望用自然语言搜索灵感，而不必记住标题或标签。
5. 作为编导，我希望让 Agent 比较多条灵感，但不自动写入当前剧本。
6. 作为编导，我希望把选中的灵感送入项目草稿，以便继续创作。
7. 作为编导，我希望明确把灵感登记为项目事实，以便后续连续性检查可以使用它。
8. 作为编导，我希望把灵感作为 Skill 案例，而不是直接变成写作规则。
9. 作为编导，我希望编辑、归档和删除灵感，以便保持库内内容可管理。
10. 作为编导，我希望灵感库按项目或用户范围隔离，以便不同作品互不混淆。
11. 作为编导，我希望看到灵感是否已经进入某个项目，以便避免重复使用或误修改。
12. 作为编导，我希望灵感库不会自动进入每次对话上下文，以便控制上下文和成本。

## Implementation Decisions

- 灵感条目包含内容、类型、标题、标签、来源、作用域、创建时间、状态和关联项目。
- 第一版支持文本和图片元数据；大文件和复杂文档继续通过项目参考文件能力处理，灵感库保存引用而不是复制全文。
- 灵感有明确状态：独立灵感、任务参考、项目草稿内容、项目事实、Skill 候选、已归档。
- 从对话保存时默认不进入项目；加入项目或登记为事实必须由用户明确表达或确认。
- 灵感搜索支持关键词、标签、类型和当前项目相关性；语义推荐属于后续能力。
- Agent 使用灵感时必须返回来源，并区分原文、用户选择和模型组合内容。
- 灵感库不能直接修改正式项目文件。进入项目必须经过草稿或领域工具流程。
- 灵感库与 Skill、项目、Agent 配置分开存储和授权；删除灵感不删除已提交项目版本或已发布 Skill。
- 首页入口提供查看和搜索，主要操作仍然可以由自然语言完成。
- 个人灵感默认私有；项目共享范围需要用户明确设置。

## Testing Decisions

- 验证从对话保存、编辑、搜索、归档和删除的外部结果。
- 验证灵感默认不会出现在项目正式 Artifact 或自动上下文中。
- 验证用户选择“作为参考”“加入草稿”“登记为事实”后，三种状态产生不同结果。
- 验证灵感来源、作用域和关联项目在读取时保持准确。
- 验证删除灵感不会修改正式版本或已生成的 Skill。
- 验证项目作用域灵感不能在其他项目中自动可见。
- 验证大文件只保存受控引用，不绕过项目参考文件的大小和权限限制。

## Out of Scope

- 社区内容流、点赞、关注、排行榜和市场交易。
- 自动从所有聊天记录批量抽取灵感。
- 无确认地把灵感写入正式剧本或项目事实。
- 用灵感库替代项目参考文件管理。
- 第一版的复杂语义推荐和自动剧情生成。

## Further Notes

灵感库的核心不是“多存内容”，而是让用户随时决定一条内容的下一步去向：继续保留、拿来讨论、送入草稿、登记为事实，还是提炼成 Skill。
