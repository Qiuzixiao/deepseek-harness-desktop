# 工作台外部文件同步与冲突保护

## 问题证据

会话 session-f6e1a1ca-dfa4-400d-821d-d4a18e5e4f7e：seq 89542 写入无阿豪正文、89543 成功；98349/99619 又读到旧稿；101980 再写，102087 零匹配，用户仍反馈旧内容。原日志没有编辑器 HTTP 保存记录，不能断定第一次回退的写入者。

旧 Workspace 仅轮询文件树，已打开文件再次点击不会读取正文。CodeMirror/Milkdown 只处理 initialDoc。故目录更新不代表编辑缓冲更新。

## 实现

- 主链路为项目目录递归 fs.watch → 同源 SSE → Workspace 立即读取并更新正文与文件树；监听目录而非文件 inode，覆盖新增子目录和原子替换。连接断开自动重连，每次连接发送 ready 补查；连续事件在读取期间排队，完成后下一帧继续校验；关闭项目/Host 释放订阅。30 秒轮询仅用于漏事件兜底；返回应用、标签切换、手动目录刷新补查。GET sync=1 只返回磁盘正文，不扫描/写入历史；文件响应 no-store。
- 一个轮询批次同时只运行一次。请求返回时检查对应文档对象、保存锁及输入法组合状态；关闭/重开、编辑、保存发生后丢弃过期响应。
- 干净缓冲接收外部更新；有本地修改或文件消失时保留缓冲，暂停自动保存。同步失败也暂停自动保存并可重试。
- CodeMirror 和 Milkdown 增加 externalUpdate 通道。保留有界光标位置和滚动位置，重置旧版本撤销历史，不回发 onChange。模式切换使用当前 draft，不重放旧 externalUpdate。
- 冲突并排显示本地/磁盘内容。默认先将本地稿写到唯一副本路径（create-if-absent），再读取当前磁盘版本。备份失败不能丢掉本地稿；备份期间新输入不被替换。覆盖需确认，仍使用用户所见磁盘基线校验，若又发生变化仍拒绝。
- 脏缓冲每 500ms 独立备份到已有私有恢复存储；每路径写入串行。重开/恢复标签时恢复草稿并要求处理，不自动覆盖磁盘；已删除文件的恢复草稿仍可打开。正常保存仅清理匹配草稿；放弃、采用磁盘版本前等待在途备份并按内容条件清理。
- Desktop 文件保存接入可用的 ctx.fs：在内容基线检查之外以 provider version 写入，复用该 provider 与 Agent 的写锁。认证后的工作台操作使用已验证项目的 workspace-write 范围，独立于 Agent 的只读策略。没有 provider 的独立调用保留原有同步写入后备。
- Host document-sync 日志记录读取版本 SHA-256、保存期望版本、保存结果；重复不变读取去重。日志不写正文。它属于 Host 诊断日志，不会自动加入仅含 session.jsonl 的会话导出包。

## 边界

已替换原先以两秒轮询为主的方案。正常更新由 OS 文件事件直接驱动，不等待轮询或 Agent 整轮结束，不需要用户操作。它展示已写入文件，不是模型尚未落盘的 token；OS 事件丢失/监听不可用由重连、焦点校验和 30 秒低频兜底恢复。

共享 provider 的写锁不等于任意外部进程之间的原子 compare-and-swap；绕过 provider 的其他程序仍可能在最后检查后抢写。保留恢复检查点和冲突检测，不承诺阻止所有非协作写入。通过 shell 整段写错正文、同名不同路径复制稿等 Agent 语义错误不能由刷新层自动纠正。

草稿备份有最多一个轮询周期和在途 I/O 的窗口，不能承诺强杀时最后半秒输入一定落盘。未单独扩展原生退出的“放弃”回调清理备份；该路径可能在下次打开时再次提示恢复，保守保留内容。

Windows 原生实机、系统中文输入法、完整 Electron 生命周期还需专项验收；不把 jsdom composition 事件测试称为输入法实机通过。W04 完整版本历史 UI 和其他工作台功能仍暂停。

## 通知链路回归

禁用轮询的推送测试先在旧实现失败。新增连续通知/重连补查测试、真实 OS 子目录写入/原子替换/断开清理测试。目录读取也增加请求序号，防止更早响应覆盖最新文件树。
