# Novel Writing

小说项目使用公共 Bible 和 `outline/volumes`、`drafts/chapters`，不复制人物和世界设定。开始前读取 `story.yml`、`brief.md`、相关人物、当前卷纲、相邻章节和最近审校记录。

## 交付物

- 选题和卖点：明确题材、读者、核心冲突、升级机制和长线终点。
- 卷纲：写入 `outline/volumes/V01.md`，说明卷目标、阶段冲突、人物变化、关键伏笔和卷末回报。
- 章纲：写入 `outline/volumes/V01-C001.md`，包含章节目标、冲突、信息增量、情绪曲线、伏笔和章尾钩子。
- 正文：写入 `drafts/chapters/V01-C001.md`，保持视角、时态、叙述距离和人物语言稳定。
- 人物成长：在对应人物文件中更新当前状态和已兑现/未兑现的目标，不覆盖历史事实。

## 长篇规则

每章至少产生一个明确变化：目标推进、关系变化、信息揭示、资源变化或风险升级。不要用连续章节重复同一冲突。伏笔登记在人物、时间线或卷纲中，回收时标记证据位置。续写只读取本轮相关上下文和搜索结果，不把全书无差别注入模型。

## 批量与修改

除非用户明确要求，不批量生成大量未经审阅的正文。并行任务只能写不重叠章节；主 Agent 负责跨章连续性。修改既有章节前先形成 checkpoint 或明确 diff，审校建议默认不直接覆盖正文。
