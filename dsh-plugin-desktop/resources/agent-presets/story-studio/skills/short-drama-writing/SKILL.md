# Short Drama Writing

把短剧创作拆成可审阅的交付物，不一次生成无法修改的大段正文。先读取 `项目配置.yml`、`项目说明.md`、公共故事设定和本轮相关文件；如果项目不存在，先使用 `story-project` 建立项目。已有旧项目再读取对应的英文旧路径。

## 创作顺序

根据用户本轮目标选择最短路径：

1. 选题：输出一句话梗概、题材、受众、核心卖点、差异化机制和风险。
2. 人物：每个主要人物单独写入 `故事设定/人物/<稳定ID>.md`，包含目标、欲望、恐惧、能力、限制、秘密、关系和弧光。
3. 故事设定：写入 `故事设定/故事前提.md`、`世界规则.md`、`时间线.md`、`写作风格.md`，只记录已确认事实和标记过的假设。
4. 季纲：写入 `故事大纲/季纲/第01季.md`，明确本季主线、阶段目标、季终结局和下一季接口。
5. 分集纲：每集写入 `故事大纲/分集大纲/第01季-第01集.md`，至少包含开场钩子、单集目标、主要冲突、升级、反转、情绪爽点、付费卡点、结尾钩子和人物变化。
6. 正文：每集写入 `正文草稿/短剧/第01季-第01集.md`，按场次输出时间、地点、人物、动作、台词、转场和本场功能。口语化，但不牺牲因果和人物差异。

## 爽感结构

短剧每集必须回答：主角这一集想得到什么、谁阻止他、他付出了什么代价、观众在什么时刻获得情绪回报、下一集为什么必须继续看。不要把“主角变强”当作唯一爽点，优先使用信息差兑现、身份反转、打脸后果、资源升级、关系逆转和新的更大代价。构思反转、钩子或卡点前，可用 grep 按当前场景关键词检索 `灵感速记/灵感速记.md`（若存在），命中则评估是否采用，未命中直接继续。

## 连续性

生成或修改分集时读取相邻集和相关人物文件。不得提前使用尚未获得的能力、资源或信息；反转必须有前置证据。批量生成多集时按不重叠范围分工，主 Agent 汇总后检查编号、时间线、人物状态和伏笔。

## 输出边界

用户只要选题或大纲时，不擅自生成正文。用户只要求一集时，不批量生成全季。每次写入后说明文件位置、采用的假设、待确认问题和下一步。
